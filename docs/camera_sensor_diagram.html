How a Camera Sensor Sees

From photons hitting silicon to the RGB pixel values in your OpenCV frame

01 Light → Lens → Sensor

Light from the scene enters through a lens, which focuses it onto a small silicon chip — the image sensor. The sensor is covered in a grid of millions of tiny light detectors called photosites. Each photosite converts photons into an electrical charge: more light = higher voltage.

02 The Bayer Filter Mosaic

Each photosite only measures brightness, not color. To get color, a mosaic of tiny colored filters sits on top of the sensor. Each photosite sees through only one filter — red, green, or blue. Notice there are twice as many green filters: human eyes are most sensitive to green, so extra green resolution means sharper-looking images. Click any cell to inspect it.

03 Demosaicing — Interpolating Color

Each photosite only knows one color channel. To produce a full RGB value for each pixel, the camera's processor interpolates the missing channels from its neighbors. This 2×2 Bayer group becomes one pixel with all three channels. The color you see is partly real measurement, partly educated guess.

04 The Final Frame — A Grid of RGB Pixels

The result is a 2D grid of pixels, each with an (R, G, B) value. This is exactly what OpenCV gives you as a NumPy array. For a 640×480 frame, that's 307,200 pixels, each with 3 values, captured 30 times per second. Toggle the view to see what different representations look like.

Resolution: 640 × 480 Pixels: 307,200 Values/frame: 921,600 FPS: 30
Key takeaway for tracking: Your camera gives you nothing but a flat grid of RGB numbers — no depth, no object identity, no motion. Everything your tracker "knows" about the rocket (where it is, how fast it's moving, what it is) must be inferred from these numbers alone. That's what makes computer vision both challenging and fascinating.
